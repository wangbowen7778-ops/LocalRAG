## 阶段三：存储层实现（第 6-8 天）✅ v1.1/v1.1.1 已升级为纯 JS / WASM 方案

### 目标
完成 vectra 向量库、sql.js (WASM SQLite)、keytar 的封装。

### 任务清单
- [x] ~~`python-bridge.ts`：启动本地 ChromaDB HTTP 服务~~（v1.1 已删除）
- [x] `vector-store.ts`：基于 **vectra** 封装 LocalIndex CRUD
  - 每个知识库一个 `userData/index/<kbId>/index.json`
  - 提供 `addChunks` / `vectorSearch` / `deleteChunksByDoc` / `deleteCollection`
- [x] `secure-store.ts`：keytar 包装，统一 Key 名规范
- [x] `storage.ts`：基于 **sql.js**（v1.1.1）替代 better-sqlite3
  - 表结构：settings / providers / knowledge_bases / documents / sessions / messages
  - 全内存运行 + 写后 `db.export()` 落盘
  - `initStorage()` 改为 async（加载 WASM）

### 交付物
- 可在主进程内创建/删除知识库、读写 API Key、保存对话消息、写入并检索向量。

> **架构变更记录**：
> - **v1.1**：ChromaDB（Python） → vectra（纯 JS）
> - **v1.1.1**：better-sqlite3（native 编译） → sql.js（WASM，零编译）
> 详见 `docs/开发进度.md` 与 `CLAUDE.md` 顶部。

## 阶段四：文档处理（第 9-12 天）

### 目标
支持多格式文档解析、分块、批量向量化入库。

### 任务清单
- [x] `document-processor.ts`：PDF / DOCX / MD / TXT 解析

  - [x] MD：`marked` 解析后去除 HTML

- [x] 文本分块：滑动窗口（默认 500 字 + 50 重叠）
- [x] 批量上传：流式处理 + 进度事件
- [x] 调用 Embedding API，生成向量
- [x] 写入 vectra 索引（带元数据：docId / filename / chunkIndex）

### 交付物
- 上传一份 PDF 后能在 vectra 索引中查询到分块向量。

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| vectra 索引过大 | 单库 > 5 万片段时检索变慢 | 切换到 hnswlib-node / lancedb；或按文档分片 |
| API 限流 | 上传/对话失败 | 增加重试 + 指数退避 |
| 打包体积过大 | 安装包 > 200MB | 已通过纯 JS 方案避免（实测 < 150MB） |
| SQLite native 模块编译失败 | Windows 兼容问题 | 锁定 `better-sqlite3` 版本与预编译二进制；提供 `@electron/rebuild` 指引 |
| vectra 索引文件并发损坏 | 数据丢失 | 写入用串行队列；提供「重建索引」功能（未来） |

## 度量

- 每个阶段结束统计：完成度、剩余工时、阻塞项。
- 关键 KPI：单文档上传到可检索 < 30 秒；首问响应 < 3 秒。
- 安装包大小：< 150MB（vectra 方案可达成）。
