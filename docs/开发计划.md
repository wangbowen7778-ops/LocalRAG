## 阶段四点五：智能切分 v1.2.1

### 目标
把「单一滑动窗口 char-based 切分」升级为「**按文件类型分发 + token-based 切分**」，让切片语义更完整、结构更可读。

### 任务清单
- [x] **`src/main/chunkers/`（新建）**：
  - `tokenizer.ts`：`gpt-tokenizer@3.4` cl100k_base（与 OpenAI text-embedding-3 同源）
  - `recursive.ts`（A+C）：LangChain 递归分隔符 `[\n\n → \n → 句号群 → 词 → 字符]`
  - `markdown.ts`（B+A+C）：`marked.lexer` 结构感知 + 标题面包屑 + 代码块/表格原子化
  - `pdf-layout.ts`（E+A+C）：pdfjs items 按 (页, y, x) 排版 + 跳页眉页脚（数字归一化）
  - `index.ts`：分发器
  - `gpt-tokenizer.d.ts`：TS moduleResolution=Node shim
- [x] **`document-processor.ts` 改造**：
  - 删 `splitChunks`；新增 `extractPdfTextItems`（带坐标）
  - `processAndIndexDoc` 按扩展名分发：`.pdf` 走 items + pdfItemsToText + recursive（失败 OCR 兜底），`.md` 走 markdownChunk，DOCX/TXT 走 extractText + recursive
- [x] **Settings**：`chunkSize` 500→800 tokens、`chunkOverlap` 50→100 tokens；UI 标签加 `(tokens)` 后缀
- [x] **`scripts/chunker-selftest.js`（新增）**：跑 3 种典型输入验证切分效果

### 交付物
- 纯文本：4 段切 2 chunks（每段 ~150-200 token）
- Markdown：4 级标题切 4 chunks，每个带 `【H1 > H2】` 面包屑
- 文本层 PDF：3 页 + 页眉页脚 → 正确去重页眉页脚 → 章节切分
- OCR PDF：降级到 A+C 切分（拿不到坐标）

### 已知边界
- PDF 不做分栏检测（双栏论文/期刊可能误读），如未来需要可加列检测
- gpt-tokenizer 字典 ~1.5MB，进程驻留

## 阶段五点六：对话上下文优化（v1.2.2 + v1.2.3）

### 目标
解决多轮对话 RAG 的两个核心痛点：
1. **指代 / 省略问句召回差**——"它是什么？" / "哪一章？" / "那关于 X 呢？" 类短问句 embed 后与上一轮实体向量偏离，命中率从 90% 跌到 30-50%
2. **长会话 history 越界**——session 超过 10 轮后，改写 LLM 自己也看不完 100 条历史；同时跨 session 的"我们之前聊过 X 吗"无法回答

### 任务清单

#### v1.2.2 查询改写

- [x] **`src/main/api-client.ts::rewriteQuery(provider, key, model, messages, currentMsgId, query, sessionId)`（~150 行）**：
  - **跳过判定**：`ANAPHORIC_RE = /[它他她这那]|刚才|那个/`；query 长度 ≥ 6 且不匹配 → 直接返回原 query（0 LLM 调用）
  - **改写 prompt**（`REWRITE_PROMPT`）：给 LLM 看压缩后的最近 8 条历史 + 当前 query，输出**改写后的一行 query**（无解释）
  - **进程内缓存**：`rewriteCache: Map<sessionId, Map<key, string>>`；key = `(lastUserContent + '|' + currentQuery)`；命中后 0 LLM 调用
  - **失败回退**：Provider 4xx/5xx/网络超时 → `console.warn` + 返回原 query，不阻塞主流程
  - **导出** `clearRewriteCache()`：设置变更时主动清空
- [x] **`src/main/document-processor.ts::resolveRewriterProvider(settings)`**——镜像 `resolveEmbeddingProvider`：
  - `rewriterProviderId` 非空 → 用其 Provider / `rewriterModel`
  - 空 → 复用 `defaultProviderId` / `defaultModel`
- [x] **`src/main/ipc-handlers.ts::applyQueryRewrite(sessionId, userMsgId, chatApiKey, settings, userContent)`**：
  - `enableQueryRewrite === false` → 直接返回原 userContent
  - 调 `rewriteQuery`；失败/异常 → 静默回退
- [x] **simple 模式**：`runSimpleChat` 用 `effectiveQuery` 替换原 `payload.content`（embed + hybridSearch + prompt 全部用 effectiveQuery）
- [x] **agent 模式**：`AgentInput.effectiveUserContent?: string` 透传；`agent.ts` 内部 `effectiveUserContent ?? userContent`
- [x] **Settings 增 3 字段**：`enableQueryRewrite?: boolean`（默认 `true`）/ `rewriterProviderId?: string` / `rewriterModel?: string`
- [x] **SettingsDialog**：常规 tab 加 3 行 UI（checkbox + 改写 Provider 下拉 + 改写模型输入框）

#### v1.2.3 长会话上下文

- [x] **`src/main/api-client.ts::buildRewriteHistory(messages, currentMsgId)`**：
  - **4 步压缩**：过滤 tool/系统消息 → 必带 firstUser 锚定 → 取最近 10 条 → 倒序按 2500 字预算填
  - **assistant 截断**：单条 > 500 字时截到 300 字 + `…`（保留前 300 字核心）
  - **`REWRITE_HISTORY` 常量**：`MAX_MESSAGES=10` / `ASSISTANT_TRUNCATE_THRESHOLD=500` / `ASSISTANT_TRUNCATE_LENGTH=300` / `MAX_CHARS=2500`
- [x] **`src/main/api-client.ts::summarizeConversation(messages, provider, key, model)`**：
  - **prompt 模板**（`SUMMARIZE_PROMPT`）：要求 LLM 输出 `summary` 一段 + `keyTopics` 列表 + `keyEntities` 列表
  - **解析**：尝试 JSON.parse，失败回退到"全文当 summary、keyTopics/Entities 空"
- [x] **`src/main/storage.ts` 新增 `session_summaries` 表**：
  - 列：`id` / `session_id` / `start_msg_id` / `end_msg_id` / `summary` / `key_topics` / `key_entities` / `created_at`
  - 索引：`(session_id, created_at DESC)`
  - **5 个 CRUD 函数**：`addSessionSummary` / `getLatestSessionSummary` / `listSessionSummaries` / `searchSessionSummaries`（跨 session SQL LIKE）/ `deleteSessionSummaries`
  - `deleteSession` 级联调 `deleteSessionSummaries`
- [x] **`src/main/ipc-handlers.ts::maybeSummarizeSession(...)`（fire-and-forget）**：
  - 触发条件：自上次摘要以来 user turn 数 ≥ `summaryTriggerTurns`（默认 20）
  - **关键**：`void maybeSummarizeSession(...)`——不 `await`，不阻塞 chat 主流程
  - 失败 `console.warn` 跳过；下次 user 消息再试
- [x] **历史摘要召回注入**：
  - `runSimpleChat`：每次发问调 `searchSessionSummaries(payload.content, 2)` 命中 top 2 → 拼 `summaryBlock` 加到 user prompt 顶部
  - `agent.ts`：fallback + 流式 final 都注入 `summaryBlock`
- [x] **Settings 增 1 字段**：`summaryTriggerTurns?: number`（默认 20；0 = 关闭）
- [x] **SettingsDialog**：周期摘要阈值数字输入框（0-200，默认 20）
- [x] **`scripts/rewrite-selftest.js`（新增）**：
  - **Part A** 11 个本地跳过判定 case（无 LLM 调用，0 凭据）
  - **Part C** 5 个 `buildRewriteHistory` case（无 LLM 调用，验证压缩逻辑）
  - **Part B** 4 个端到端 LLM case（设 `REWRITER_API_KEY` 才跑，含缓存命中验证）

### 交付物

- 用户发"哪一章？" / "它是什么？" / "刚才那个文件呢？" 类追问时，**自动改写**为自包含 query 再检索，召回率从 30-50% 回升到 80-90%
- 长 session（> 10 轮）改写 LLM 仍只看到 ≤ 2500 字 token 预算的历史
- 跨 session 的"我们之前聊过 X 吗"问题，自动从 `session_summaries` 命中 top 2 历史摘要注入到 LLM 上下文
- 周期摘要**不阻塞** chat（fire-and-forget），用户感知不到
- 默认开启；用户可在「设置 → 常规」关掉（设为 `false` / 0）

### 已知边界

- 摘要是**异步**生成——刚结束的 turn 不会立刻被检索到
- 改写 + 摘要复用同一 Provider/模型；token 消耗约 1-2K/次摘要
- `summaryTriggerTurns = 0` 关闭摘要但**保留改写**（适合不想异步调 LLM 的用户）
- v1.2.2 与 v1.2.3 不依赖 Agent 模式——简单模式同样享受改写 + 摘要收益
- `ANAPHORIC_RE` 故意只列 5 字 + 2 短语（`它他她这那` + `刚才/那个`），假阳率最低但召回不完美

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| vectra 索引过大 | 单库 > 5 万片段时检索变慢 | 切换到 hnswlib-node / lancedb；或按文档分片 |
| API 限流 | 上传/对话失败 | 增加重试 + 指数退避 |
| 打包体积过大 | 安装包 > 200MB | 已通过纯 JS 方案避免（实测 < 150MB）。OCR 首次下载模型 ~23MB 走 `userData/cache/tesseract`，不进安装包 |
| SQLite native 模块编译失败 | Windows 兼容问题 | **v1.1.1 起已彻底消除**——sql.js 是纯 WASM，无需编译。除 `keytar` 外无任何 native 依赖 |
| tesseract OCR 中文识别准确率 | 扫描件 / 图片型 PDF 公式 / 表格识别差 | tesseract 的本质限制。当前 `TextExtractor` 接口已抽象，将来可平替为云 OCR / MinerU / RapidOCR |

## 度量

- 每个阶段结束统计：完成度、剩余工时、阻塞项。
- 关键 KPI：单文档上传到可检索 < 30 秒；首问响应 < 3 秒。
- 安装包大小：< 150MB（vectra 方案可达成）。
