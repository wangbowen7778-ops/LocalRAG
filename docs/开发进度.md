### v1.2.1（2026-06-07）— 按文件类型分发的智能切分（chunkSize 改 token 单位）
- **问题**：
  1. 老的 `splitChunks` 按 500 字符硬切，PDF 没段落结构时（pdfjs 每页只插 `\n` 不插 `\n\n`，多页之间才 `\n\n`）基本是按 char 横切，句子常被腰斩
  2. char-based 单位对中英文密度不一致（500 字符 ≈ 500 CJK token / 100-150 EN token），跨语言体感差
  3. Markdown 文档的标题/代码块/表格结构在切分后完全丢失——检索时 LLM 看不到「这一段来自文档哪一节」
  4. 50 字符 overlap 太小，跨切点的语义重建基本靠运气
- **根因**：
  1. PDF 文本提取每页只插 `\n`（不是 `\n\n`），对 `splitChunks` 而言就是"一整块"，全走 `> size` 分支按 char 硬切
  2. Markdown 走 `marked.parse → strip HTML` 之后只剩纯文本，结构全丢
  3. `chunkSize` / `chunkOverlap` 单位是 char 不是 token；overlap 按 char 算不按 token
- **修复**：
  - **`src/main/chunkers/`（新建，6 个文件）**：
    - **`tokenizer.ts`**：`gpt-tokenizer@3.4.0` 的 cl100k_base 编码（与 OpenAI text-embedding-3 / gpt-4 同源）；提供 `countTokens` / `tailTokens`（按 token 边界切，不切到 token 中间）
