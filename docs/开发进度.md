### v1.1.6（2026-06-05）— 计数修复 + 扫描件 OCR + pdfjs canvas 修复 + 引用分数阈值
- **问题**：
  1. 上传后删除文档，docCount / chunkCount 计数变负数
  2. 扫描件 / 图片型 PDF 上传后报「文档内容为空或无法解析」——pdfjs 文本层为空时只能干瞪眼
  3. 即便开了 OCR，处理图片型 PDF 时报 `Cannot find module '../build/Release/canvas.node'`——pdfjs 默认 NodeCanvasFactory 找不到 `node-canvas`（要 native 编译）原生模块
  4. 多个相似文档时，问其中一个会被三个文档的引用污染回答
- **根因**：
  1. `updateKBStats` 在 `DOC_DELETE` 时无条件 `-1`，但 `DOC_UPLOAD` 只在成功分支 `+1`——failed / processing 文档被删除时把计数拉到负数
  2. 纯文本 PDF 提取器对扫描件输出 0-2 字符，没 OCR fallback
  3. pdfjs-dist@3.11.174 把 `canvas`（node-canvas 原版）列为 optionalDependencies，`require("canvas")` 会去加载 `.node` 二进制，npm install --ignore-scripts 模式下没编译。pdfjs 自带的 try/catch 吞掉了启动时的报错（只 warn "Cannot polyfill DOMMatrix"），但 `globalThis.DOMMatrix` 仍是 undefined，后续 `page.render()` 内部用到 DOMMatrix 就炸
  4. `CHAT_SEND` 的 `vectorSearch` 不做分数过滤，top-K=5 把整个 KB 里最像的 5 个 chunk 全塞进 LLM 上下文
- **修复**：
  - `src/shared/types.ts`：`Settings` 新增 `citationScoreThreshold: number`（0-1，默认 0.4）；`DocProgressEvent.stage` 联合类型加 `'ocr'`
  - `src/shared/constants.ts`：`IPC` 加 `DOC_OCR_TEST: 'doc:ocrTest'`
  - `src/main/storage.ts`：
    - `DEFAULT_SETTINGS` 加 `enableOcr: false` + `citationScoreThreshold: 0.4`
    - `initStorage()` 加幂等迁移：`UPDATE knowledge_bases SET doc_count/chunk_count = (SELECT COUNT/SUM FROM documents WHERE status='ready')` 一次性修复历史负数
  - `src/main/ipc-handlers.ts`：
    - `DOC_DELETE`：`updateKBStats(kb.kbId, doc.chunkCount > 0 ? -1 : 0, -doc.chunkCount)`（条件回退）
    - `CHAT_SEND` 检索后过滤 `score >= settings.citationScoreThreshold`，过滤后为空时明确告诉 LLM「未检索到相关文档」走通识
    - 新增 `DOC_OCR_TEST` handler：调 `runOcrSelfTest()`，用 `@napi-rs/canvas` 画测试图丢给 tesseract worker，返回 `{ok, text, latencyMs, modelPath, error?}`
  - `src/main/document-processor.ts`（**大改**）：
    - 弃用 `pdf-parse`，改用 `pdfjs-dist@3.11.174`（legacy build，Node 主线程无需 worker）
    - 文本提取器抽象为 `TextExtractor` 接口（`name` / `accepts` / `extract`）
    - 新增 `PdfjsTextExtractor`（文本层 PDF）和 `TesseractOcrExtractor`（扫描件 fallback，用 `@napi-rs/canvas` 渲染 PDF 每页到 PNG，再 tesseract.js OCR）
    - module-level `tesseractWorkerPromise` 缓存 worker（首次会下载 ~23MB 中英模型到 `userData/cache/tesseract`，之后离线）
    - `selectExtractors()` 根据 `settings.enableOcr` 决定是否加 OCR
    - `extractText()` 顺序试，阈值 10 字符以下算"提取失败"自动 fallback
    - `extractText()` 修误导日志：若无下一个抽取器，正确显示「已无更多抽取器」+ 提示开 OCR
    - 新增 `runOcrSelfTest()`：独立 OCR 诊断入口
  - **`src/main/pdfjs-shim.ts`（新增）**：
    - 在 `require('pdfjs-dist/legacy/build/pdf.js')` 之前先 `globalThis.DOMMatrix = NapiDOMMatrix`、`globalThis.Path2D = NapiPath2D`（都用 `@napi-rs/canvas` 版本）
    - 这样 pdfjs 的启动 IIFE 检查到 global 已有值，直接 return，不会去 `require("canvas")`
  - `src/main/document-processor.ts`：自定义 `NapiCanvasFactory`（create/reset/destroy），**必须传给 `getDocument()`**——getDocument 内部 `new DefaultCanvasFactory()` 在 Node 上即 NodeCanvasFactory，annotation 渲染时 `require("canvas")` 会炸。两个抽取器（`PdfjsTextExtractor` + `TesseractOcrExtractor`）都传
  - `src/main/preload.ts`：`window.api.doc.ocrTest` 暴露
  - `src/renderer/types/index.ts`：`ElectronApi.doc.ocrTest` 签名
  - `src/renderer/services/electronAPI.ts`：`api.ocrTest()` 包装
  - `src/renderer/components/Layout/DocumentPanel.tsx`：进度条 stage 文案加 OCR 分支
  - `src/renderer/components/Settings/SettingsDialog.tsx`：
    - 「OCR 识别（扫描件）」复选框 + 解释文字
    - 「测试 OCR」按钮（独立验证管线）
    - 「引用分数阈值」滑块（0-1 步长 0.05，实时显示当前值）+ 解释
