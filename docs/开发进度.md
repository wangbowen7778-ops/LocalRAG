## 架构变更记录

### v1.1.5（2026-06-04）— 上传 404 + 输入框下沉
- **问题**：
  1. 上传文档后报错 `Request failed with status code 404`，文档没有解析
  2. 用户输入框和发送按钮「在页面中间下方」，与期望的「页面最下方」不符
- **根因**：
  1. v1.1.3 引入的 bug：把 `embeddingModel` 字段预设改成了推理模型（`deepseek-reasoner` / `qwq-plus`），但 `api-client.ts::embedText` 仍把 `provider.embeddingModel` 传给 `/embeddings` 接口——DeepSeek 没有原生 embedding 接口，Qwen 的 `text-embedding-v3` 接口也不接受 `qwq-plus` 这个模型名。
     **更关键**：即使把 `embeddingModel` 改回 `text-embedding-3-small`，DeepSeek 服务**根本就没有 `/embeddings` 这个端点**——任何模型名都会 404。这是 DeepSeek 的根本限制，模型名修不修都不行。
  2. App.tsx 在 `<main>` 里给 ChatArea 又包了一层 `<div className="flex-1 min-w-0">`（没有 `h-full`），导致 ChatArea 在没有显式高度约束时按内容高度渲染——session sidebar 有几个会话项时，ChatArea 就只有那么高，InputBox 自然不在页面底部
- **修复**：
  - `src/shared/types.ts`：
    - `ProviderConfig` 新增 `reasoningModel?: string`（独立于 embedding）
    - `Settings` 新增 `embeddingProviderId?: string`（全局「Embedding Provider」开关）
  - `src/shared/constants.ts`：`PROVIDER_PRESETS` 三个预设都补 `reasoningModel`，同时把 `embeddingModel` 改回真实 embedding 模型
  - `src/main/storage.ts`：
    - `providers` 表加 `reasoning_model TEXT` 列
    - `initStorage()` 增加迁移：旧 `embedding_model`（实际存的是 v1.1.3 的「思考模型」值）搬到 `reasoning_model`，再按 provider id 复位 `embedding_model`
    - `listProviders` / `upsertProvider` 同步 `reasoningModel`
  - `src/main/document-processor.ts`：`resolveEmbeddingProvider` 优先用 `settings.embeddingProviderId`（这样 DeepSeek 用户也能用 OpenAI 跑 embedding）
  - `src/main/ipc-handlers.ts`：
    - `PROVIDER_UPSERT` 透传 `reasoningModel`
    - `CHAT_SEND` 的「查询向量」也用 `resolveEmbeddingProvider()`（之前直接用 chat provider，DeepSeek 会 404）
  - `src/main/api-client.ts`：`embedText` 捕获 axios 404 → 转成对用户友好的提示「XX 不支持 embedding 接口，请到设置 → 常规 → Embedding Provider 选择支持 embedding 的服务」
  - `src/renderer/components/Settings/SettingsDialog.tsx`：
    - 列表行新增独立的「Thinking 模型（可选，推理用）」输入框
    - 「Thinking 模型」输入框改回「Embedding 模型」
    - 常规 tab 新增「Embedding Provider」下拉，默认「（与 Chat 共用）」
  - `src/renderer/App.tsx`：**核心修复**——给 ChatArea 的外层包装加 `h-full min-h-0`，让 ChatArea 真正撑满 `<main>` 的高度，InputBox 才会落在页面底部
  - `src/renderer/components/Layout/ChatArea.tsx`：`flex-1 flex min-w-0` → `flex-1 flex min-w-0 h-full min-h-0`（外层与聊天列都加显式高度，避免高度塌陷）
  - `src/renderer/components/Chat/MessageList.tsx` / `Layout/DocumentPanel.tsx`：加 `min-h-0` / `h-full min-h-0` 同样为 flex 子项铺路
  - `src/renderer/components/Chat/InputBox.tsx`：加 `flex-shrink-0`，确保不被压缩
- **用户操作指引**：DeepSeek 用户要上传文档，需新增一个 OpenAI 或 Qwen Provider（填好 API Key），然后到「设置 → 常规 → Embedding Provider」选它。Chat 仍用 DeepSeek，embedding 走 OpenAI/Qwen
- **用户文档**：CLAUDE.md、README.md、开发进度.md 全部同步更新

### v1.1.4（2026-06-04）— 设置页「保存后不显示」修复
- **问题**：添加并保存一个 AI 服务后，再次打开「设置」对话框，列表里看不到刚刚保存的 Provider
- **根因**：
  - SettingsDialog 一直挂在 App 里（`if (!open) return null`），不会因 open 切换重挂载
  - 内部 `list` / `general` / `tab` 状态被 React 保留，重新打开时 `useEffect([open, providers, settings])` 触发的时机受 React 调度影响，可能在 props 已变更但本地 state 还没重置的窗口期渲染空列表
  - 「保存」按钮只看 `tab`：`tab === 'general'` 时 `p` 是 `undefined`，App 端就不会调 `upsertProvider`，看似「保存」其实没存
- **修复**：
  - `src/renderer/App.tsx`：给 `<SettingsDialog>` 加 `key={settings-${open}-${providers.length}-${ids}}`，**每次打开都重挂载**，`list`/`general`/`tab` 状态完全从 props 派生
  - `src/renderer/components/Settings/SettingsDialog.tsx`：「保存」按钮改为 `onSave(list, general)`，同时保存两侧（不再因当前 tab 漏保存）
- **用户文档**：CLAUDE.md、README.md、开发进度.md 全部同步更新

### v1.1.3（2026-06-04）— 设置页测试连接修复
- **问题**：用户在「AI 服务」页填写好 DeepSeek 后点击「测试连接」，后端报

- **修复**：
  - `src/main/ipc-handlers.ts`：`PROVIDER_TEST` 改为接受完整 `{ config, apiKey }`，并改用 `/chat/completions`（max_tokens=1）做探活——OpenAI 兼容协议各厂商都支持，比 `/embeddings` 通用
  - `src/main/preload.ts`、`src/renderer/types/index.ts`、`src/renderer/services/electronAPI.ts`：`testProvider` 同步改为传完整 config
  - `src/renderer/components/Settings/SettingsDialog.tsx`：
    - `testRow` 加 `try/catch`，错误用 toast 提示（不再静默失败）
    - 表单输入不全时直接 toast 提示并 return
    - 「Embedding 模型」字段 placeholder 改为「Thinking 模型」
  - `src/shared/constants.ts`：`PROVIDER_PRESETS.deepseek.embeddingModel` → `deepseek-reasoner`，`qwen` → `qwq-plus`
- **用户文档**：CLAUDE.md、README.md、开发进度.md 全部同步更新

### v1.1.2（2026-06-04）— 启动链路修复
- **问题**：`npm run dev` 启动后主进程依次报 5 个错误（均为首启期问题）
  1. `dist/main/main.js not found`：因 `rootDir: src` + `outDir: dist/main`，产物多嵌一层 `main/`
  2. `Cannot find module 'D:\codelLocalRAG\dist\main\main. s'`：Electron 在打包 dist 时被并发进程 SIGTERM 杀掉
  3. `ERR_REQUIRE_ESM uuid@13`：vectra@0.15 依赖的 uuid@13 是 ESM-only，CJS 加载失败
  4. `Cannot find module 'wink-bm25-text-search'`：vectra@0.10.1 package.json 漏声明这些 wink 依赖
  5. `File is not defined`：vectra 入口 `index.js` 会 `__exportStar` 拉入 `WebFetcher → cheerio → undici`（依赖浏览器 `File` 全局）
  6. `ENOENT dist\dist\sql-wasm.wasm`：sql.js 的 `exports` 屏蔽了 `./package.json`，且入口 `path.dirname` 拿到的目录再拼 `dist/` 多了一层
- **修复**：
  - `tsconfig.main.json`：`outDir` 改 `dist`，`rootDir` 保持 `src`（让 `dist/main/main.js` 与 `package.json.main` 对齐）
  - `package.json`：`vectra` 0.15 → **0.10.1**（最后一个用 uuid@9 的版本，且 0.4.4 那个少括号的 bug 已修）；`uuid` 14 → **9.0.1**（CJS 入口）
  - `package.json`：新增 `wink-bm25-text-search`、`wink-nlp`、`wink-eng-lite-web-model`（vectra 0.10.1 运行时实际 require 但 package.json 漏声明）
  - `src/main/vector-store.ts`：绕过 `vectra/index`，直接 `import { LocalIndex } from 'vectra/lib/LocalIndex'` + `import type { MetadataFilter } from 'vectra/lib/types'`，避开 WebFetcher
  - `src/main/storage.ts`：`require.resolve('sql.js/package.json')` → `require.resolve('sql.js')`，不再拼额外 `dist/`
  - `node_modules/electron/path.txt`：补回被破坏的 `path.txt`（Electron 二进制需 `electron.exe` 字符串，且无尾随换行）
  - `node_modules/electron/dist/`：手动解压 `electron-v28.3.3-win32-x64.zip`（`npm install --ignore-scripts` 跳过了 postinstall，extract-zip 在某些环境下又只解压第一个 entry；改用 `unzip` 一次性补齐）
- **用户文档**：CLAUDE.md、README.md、开发进度.md 全部同步更新

### v1.1.1（2026-06-04）

- **影响**：
  - `package.json`：`better-sqlite3` + `@types/better-sqlite3` → `sql.js`
  - `src/main/storage.ts` 整体重写：基于 sql.js，提供兼容 better-sqlite3 的 `prep()` 包装
  - `src/main/main.ts`：`await initStorage()` 改为 async（加载 WASM）
  - `src/main/ipc-handlers.ts`：移除对 `initStorage` 的同步调用
  - 写入策略：每次写操作后 `db.export()` 落盘
  - **彻底消除 native 编译依赖**：除 `keytar` 外，sql.js 是纯 WASM
