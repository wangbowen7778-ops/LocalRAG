## 〇、系统大框架：端到端数据流（摄入 + 问答）

整个系统有**两条主线**，通过**本地向量库 + BM25 索引**这个持久化层连接：
- ① **文档摄入链路**（建库）：上传 → 解析 → 切分 → 向量化 → 入库
- ② **问答检索链路**（使用）：提问 → query 处理 → 混合检索 → rerank → LLM 作答

```mermaid
flowchart TD
    F["用户上传文档<br/>PDF / DOCX / MD / TXT"]
    F --> EX["解析提取文本<br/>document-processor.ts"]
    EX --> CK["智能切分<br/>chunkers/"]
    CK --> PF["Contextual 前缀<br/>文档标题+摘要"]
    PF --> EM["批量 Embedding<br/>embedding API"]
    EM --> W1[("vectra 向量库<br/>index.json + chunks.json")]
    EM --> W2[("BM25 索引<br/>bm25.docs.json")]

    W1 -. "向量检索" .-> SR
    W2 -. "BM25 检索" .-> SR

    Q["用户提问"]
    Q --> PL["query 预处理<br/>stripNoise + planSearchQuery"]
    PL --> QS["检索 query 1-3 条"]
    QS --> VW["embedText 向量化"]
    VW --> SR["混合检索 RRF 融合"]
    SR --> RR["rerank LLM 重排"]
    RR --> TK["topK 结果 + 阈值过滤"]
    TK --> LLM["LLM 作答<br/>simple / agent"]
    LLM --> A["回答 + 引用"]
```

```mermaid
    T1 --> D2

    P6 --> C0
    M2 --> C0
    D2 --> C0

    C0["chunkDocument 分发切分<br/>chunkers/index.ts"]
    C0 --> C1{"input.type?"}

    C1 -->|plain| C3["recursiveSplit<br/>递归分隔符 切到 token<br/>\\n\\n→\\n→句号群→词→字<br/>A+C"]
    C2 --> C4["rawChunks[]<br/>单位=token<br/>默认 chunkSize=800 overlap=100"]
    C3 --> C4

    C4 --> CX["buildContextPrefix<br/>【文档:filename】+【摘要:首段200字】"]
    CX --> C5["chunks = prefix + raw<br/>(同份带前缀文本喂 vectra 和 BM25)"]

    C5 --> E1["resolveEmbeddingProvider<br/>(独立 embeddingProviderId)"]
    E1 --> E2["批量 embedText<br/>BATCH=10 并发"]
    E2 --> E3["vectors: number[][]"]

    E3 --> W1["addChunks → vectra upsertItem<br/>id=docId__chunkIndex<br/>metadata: docId/filename/chunkIndex"]
    E3 --> W2["bm25AddDocs → BM25 索引<br/>同 id, 同带前缀文本"]
    W1 --> ST["updateKBStats docCount+1 chunkCount+N<br/>状态=ready"]
    W2 --> ST
```

**解析要点**：

| 文件类型 | 解析方式 | 切分器 |
|---|---|---|
| PDF（文本层）| `pdfjs-dist` 拿带坐标 items → `pdfItemsToText` 按版面重排 + 跳页眉页脚 | recursive（A+C）|
| PDF（扫描件）| `pdfjs` 渲染页为 PNG → `tesseract.js` OCR（chi_sim+eng）| recursive（A+C）|
| Markdown | 读原始 md | markdown 结构感知（B+A+C，标题面包屑 + 代码块/表格原子化）|
| DOCX | `mammoth.extractRawText` | recursive（A+C）|
| TXT | `iconv-lite` 编码识别（utf-16/utf-8/gbk）| recursive（A+C）|

> 切分单位是 **token**（`gpt-tokenizer` cl100k_base），默认 `chunkSize=800 / chunkOverlap=100`。
> 每个 chunk 前会拼 **Contextual 前缀**（`【文档:文件名】+【摘要:首段200字】`），同份带前缀文本同时写入 vectra 和 BM25。

### 〇.2 向量化与存储：用什么向量数据库

```mermaid
flowchart TD
    subgraph 向量化
        E0["chunk 文本<br/>(带 Contextual 前缀)"]
        E0 --> E1["embedText<br/>api-client.ts"]
        E1 --> E2["调 embedding Provider<br/>/embeddings 端点"]
        E2 --> E3["number[] 向量<br/>(维度由模型定, 如 1536)"]
    end

    subgraph 存储["本地持久化 userData/index/kbId/"]
        direction TB
        V["vectra 向量库<br/>(纯 JS, JSON 持久化, 零依赖)"]
        V --> V1["index.json<br/>主索引 LocalIndex"]
        V --> V2["chunks.json<br/>id → text 映射<br/>(vectra IndexItem 不存 text)"]
        B["BM25 索引<br/>(wink-bm25-text-search)"]
        B --> B1["bm25.docs.json<br/>id → {text,docId,filename,chunkIndex}"]
    end

    E3 --> V
    E3 --> B

    V -. "id 格式 = docId__chunkIndex<br/>metadata.docId 可过滤" .- B
```

**为什么是 vectra + wink-bm25**：

- **vectra**（纯 JS 向量库）：替代了早期的 ChromaDB（需 Python 子进程）。JSON 文件持久化，零 native 编译，零外部运行时。每个 KB 一个目录 `userData/index/<kbId>/`。
  - `index.json`：主索引（向量 + metadata，`docId` 字段可过滤）
  - `chunks.json`：`id → text` 映射（因为 vectra 的 IndexItem 不存 text，单独存一份）
- **wink-bm25-text-search**：每个 KB 一份 `bm25.docs.json`，做精确术语（错误码、API 名、专有名词）召回。与 vectra 共用同一套 chunk id（`docId__chunkIndex`），便于 RRF 融合对齐。
- **sql.js**（纯 WASM SQLite）：存对话历史、文档元数据、session 摘要（`chat.db`）。
- **keytar**：API Key 存 Windows 凭据管理器，不明文落盘。

> **零外部运行时**：无 Python / 无 Docker / 无 native 编译（sql.js 是 WASM，vectra/wink 是纯 JS）。打包后安装即用。

### 〇.3 问答检索链路：topK 结果怎么来

```mermaid
flowchart TD
    Q0["用户提问<br/>'请问一下它的限流呢'"]
    Q0 --> Q1["stripNoise<br/>剥寒暄/尾巴/句末'呢'<br/>→ '它的限流'"]
    Q1 --> Q2["planSearchQuery<br/>小 LLM 产 QueryPlan"]
    Q2 --> Q3["searchQueries 1-3 条<br/>'OpenAI API 限流策略'"]

    Q3 --> Q4["并发 embedText<br/>每条 query 转向量"]
    Q4 --> VEC["query 向量[]"]

    VEC --> H1["向量检索<br/>vectra queryItems (余弦相似度)"]
    Q3 --> H2["BM25 检索<br/>wink-bm25 (b=0.5)"]
    H1 --> R1["向量结果 按相似度排序"]
    H2 --> R2["BM25 结果 按分数排序"]

    R1 --> RRF["RRF 融合<br/>score = 1/(30+rankVec) + 1/(30+rankBM25)<br/>归一化 [0,1]"]
    R2 --> RRF
    RRF --> CAN["fetchTopK = max(topK,20) 候选<br/>去重合并"]

    CAN --> RK["rerankHits<br/>Chat Provider LLM 看语义重排<br/>10s 超时回退原顺序"]
    RK --> SL["slice(topK) 默认 8"]
    SL --> TH["score ≥ 0.4 阈值过滤"]
    TH --> TK["★ topK 最终结果<br/>SearchHit[] {docId,filename,text,score}"]

    TK --> LLM1{"模式?"}
    LLM1 -->|simple| L1["context 拼 user prompt<br/>→ chatStream 作答"]
    LLM1 -->|agent| L2["LLM 自主 search_kb/read_chunk<br/>多轮 function_calling"]
    L1 --> ANS["回答 + 引用 citations"]
    L2 --> ANS
```

**检索关键参数**：

| 参数 | 默认值 | 作用 |
|---|---|---|
| `topK` | 8 | 最终给 LLM 的 chunk 数 |
| `fetchK` | max(50, 10×topK) | RRF 融合前的候选池大小 |
| `RRF_K` | 30 | RRF 融合常数，越小低 rank 衰减越快 |
| `bm25 b` | 0.5 | BM25 length norm 力度（弱化长 chunk 优势）|
| `citationScoreThreshold` | 0.4 | 分数阈值，低于此分的 chunk 剔除（0 关闭）|
| `enableRerank` | true | LLM 语义重排（救回被 RRF 排到 topK 外的正确答案）|

```mermaid
    Main->>LLM: 第2轮 chatStream(不带 tools)<br/>【已读取的片段】+ 用户问题
    LLM-->>Main: 流式 final answer
    Main->>Main: finalizeAssistantMsg<br/>(citations = 实际 read 的 chunks)
```

## 九、简单模式 vs Agent 模式 对照

| 维度 | 简单模式 | Agent 模式 |
|---|---|---|
| 检索决策 | 固定：planSearchQuery 改写 → 一次检索 | LLM 自主：可多次 search_kb / 可 skip |
| 检索 query | 改写管线产 1-3 条 RRF 融合 | LLM 输出 sub_query（planHint 仅参考） |
| 跨 KB | 单 KB（candidateKbIds[0]） | 多 KB（selectKBs 自选 + hybridSearchMulti） |
| 中间步 | 最多 1 轮 read_chunk | 最多 maxIterations（默认 4）轮 |
| 可观测 | timing 日志 | agentTrace 折叠面板 |
| 降级 | Provider 不支持 tools → legacy 全文 | 400/422 → 降级 simple |
